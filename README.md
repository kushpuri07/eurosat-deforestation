# Satellite Image Classification and Deforestation Detection

A transfer-learning satellite image classifier trained on EuroSAT, applied to real Sentinel-2
imagery to detect land-cover change in the Brazilian Amazon (Rondônia, 2018–2024), validated
against Global Forest Watch's independently published tree-cover-loss data.

## Overview

This project has two parts:

1. **Land-cover classification.** A ResNet50 CNN, pretrained on ImageNet, was fine-tuned via
   transfer learning on the [EuroSAT](https://github.com/phelber/EuroSAT) dataset (27,000
   labeled Sentinel-2 image patches across 10 land-cover classes). Training used a two-phase
   approach: first training only a new final classification layer with the rest of the network
   frozen, then unfreezing the full network and fine-tuning at a lower learning rate.

2. **Real-world deforestation detection.** The trained classifier was applied to Sentinel-2
   imagery of a ~111 km × 111 km area in Rondônia, Brazil, comparing cloud-filtered composites
   from 2018 and 2024. Detected land-cover change was compared against the Hansen Global Forest
   Change dataset (the basis of Global Forest Watch's published statistics) as an independent
   validation.

## Results

| Metric | Value |
|---|---|
| Validation accuracy (EuroSAT) | 98.56% |
| Test accuracy (EuroSAT, held-out) | 98% |
| Original model's detected deforestation rate (2018-2024) | 60.7% |
| Corrected model's detected deforestation rate (2018-2024) | 56.4% |
| Global Forest Watch reported rate (same area/period) | 6.91% |
| Original overestimate factor | ~8.8x |
| Corrected overestimate factor | ~8.2x |

**The classifier performs excellently within its training domain** (98% test accuracy on
EuroSAT, with strong per-class precision/recall, see `results/confusion_matrix.png`). Applied
out-of-domain to Amazon imagery, it showed a **systematic bias toward misclassifying
non-forest land (particularly cleared/pasture land) as "SeaLake"**, 58.8% of sampled 2018
patches were labeled SeaLake, an implausible result for a region with no water bodies of that
scale.

**This bias was investigated and corrected.** Sixteen misclassified "SeaLake" patches were
manually inspected and relabeled with their true class (none were actually water), then used
to fine-tune only the model's final layer. This eliminated the collapse (SeaLake predictions
dropped from 58.8% to 1.0% of 2018 patches), and the prediction distribution became
qualitatively realistic across all 10 classes.

**Surprisingly, the headline deforestation rate barely changed** (60.7% -> 56.4%) despite
fixing the underlying bias. This revealed a second, independent issue: the 640m patches used
here are far coarser than the 30m pixel resolution Global Forest Watch measures at, so a
mostly-intact-forest patch containing even a small cleared section is counted entirely as
"deforested." This resolution mismatch likely accounts for most of the remaining discrepancy,
and is a distinct problem from the classification bias, requiring a different fix (finer
spatial resolution or pixel-level classification, rather than domain calibration).

This two-layer finding, a severe but correctable classification bias plus a separate and
uncorrected resolution artifact, is presented as a genuine methodological finding about the
limits of both cross-domain transfer learning and patch-based classification in remote
sensing, not a shortcoming to be hidden. See `paper/` for the full discussion.

## Method Details

- **Base architecture:** ResNet50 (ImageNet1K_V2 pretrained weights)
- **Training data:** EuroSAT RGB, 80/10/10 train/val/test split, fixed random seed
- **Data augmentation:** random horizontal/vertical flip (training only — satellite imagery
  has no canonical "up," so flips do not create unrealistic images)
- **Fine-tuning:** Phase 1 — frozen backbone, lr=0.001, 10 epochs. Phase 2 — full network
  unfrozen, lr=0.0001, 10 epochs
- **Study area:** Rondônia, Brazil (BR-364 highway corridor), a well-documented region of
  agricultural/settlement-driven deforestation
- **Imagery:** Sentinel-2 surface reflectance, cloud-masked median composites over dry-season
  months (June–September) for 2018 and 2024
- **Sampling:** 3,350 randomly sampled 64×64 patches per year (fixed seed, identical locations
  across both years) rather than exhaustive coverage, for computational tractability
- **Validation:** Hansen Global Forest Change dataset (`UMD/hansen/global_forest_change_2025_v1_13`),
  >30% canopy threshold, queried via Google Earth Engine

## Known Limitations

- **Domain shift.** The model was trained exclusively on European landscape imagery. Applied
  to a different biome (tropical rainforest and associated land use), classification accuracy
  for non-forest classes degrades substantially, as documented above.
- **Sampling, not exhaustive classification.** Due to CPU inference constraints, a random
  sample of patches was classified rather than every possible patch in the study area.
- **RGB-only imagery.** Full 13-band Sentinel-2 data (used in some remote-sensing deforestation
  literature) was not used; RGB-only classification loses spectral information that could help
  distinguish vegetation types more precisely.
- **Two time points, not a time series.** Comparing only 2018 vs. 2024 cannot distinguish
  gradual degradation, seasonal effects, or short-lived events from persistent land-cover
  change.

## Future Work

- **Benchmark against a geospatial foundation model** such as NASA/IBM's Prithvi-EO, which is
  pretrained on globally diverse multispectral imagery (800+ ecoregions) rather than a single
  region. If Prithvi generalizes to the Amazon without the SeaLake-style collapse seen here,
  that would support the conclusion that narrow, single-region training data (not transfer
  learning itself) drove the failure.
- **Disentangle the two identified error sources.** The resolution mismatch between our 640m
  patches and Global Forest Watch's native 30m pixels was proposed as an explanation for the
  remaining gap after the SeaLake bias was corrected, but this has not been directly verified
  (e.g. by aggregating GFW's pixel-level data to match patch resolution, or reclassifying at a
  finer patch size). The two error sources may still be partially entangled.

## Reproducing This Project

1. Open `notebook/research_project.ipynb` in Google Colab
2. Set up a [Kaggle API token](https://www.kaggle.com/settings) for dataset download
3. Register a [Google Earth Engine](https://code.earthengine.google.com/register) account and
   Cloud project (noncommercial/free tier), replace the placeholder project ID in the notebook
4. Run all cells top to bottom. Training is skipped automatically if a checkpoint already
   exists in your Drive — see the notebook for details.
